## 1. Executive Verdict

The 2026-10 P0/P1 run was real and durable: process guards, boot gate, retention sweeps, user_version, CAS claim machines (tickets/reminders/outbox), token encryption, SSRF guard extraction, SDK-shape tests, coverage/docs CI — all verified in place. The codebase's failure mode has **moved from platform-seam crashes to silent-state corruption in feature logic**:

1. **The events/signup cluster is broken below its own guards.** Three open issues (#344/#345/#346) share verified root causes — a `toJsonArray` that turns pre-stringified JSON into `"[]"`, a camelCase/snake_case key mismatch (`signedUp` vs `signed_up`) that deadens *every* signup guard, and a tautology-false capacity check. Worse: `replaceOptions` destroys RSVP rows via FK cascade whenever option count is unchanged — a **second data-loss path broader than #346**, invisible even after fixing the keys. `/event duplicate` silently loses ~10 columns for the same camel/snake disease (new C/H set, §2.1).
2. **YouTube is the new honeypot-class feature: destructive state bugs the suite cannot see.** A watermark UPDATE with no guild filter clobbers other guilds' pointers (INT-1, **[verified]**); one shared `last_video_id` pointer for two event classes produces a **@everyone re-ping every 5 minutes for a whole live stream** whenever an upload lands mid-stream (INT-2, **[verified]**); and `/setyoutube interval` — slash + web + docs — drives a setting **nothing reads** while the ticker is hardcoded to 5 min (INT-3, **[verified]**).
3. **The Fluxer send path still shreds payloads in production.** Multipart fallback sends build the global `FormData`, which the pinned SDK's undici `instanceof` check rejects → `JSON.stringify(FormData)` → `"{}"` on the wire (FLX-1, **[verified]**); and relay **embeds are enqueued, hashed, edit-merged — and never sent by any code path** (FLX-2, **[verified]**), violating the module's own §10.8. The test meant to cover this asserts the *wrong FormData class* (G2-2, **[verified]**) — fixture-shaped truth, C1/C2 class, still alive.
4. **Bridge edits are one-shot.** A global UNIQUE spanning terminal states + pre-enqueue snapshot mutation means the **second edit of any relayed message is silently lost forever** (BRG-1, **[verified]**); and editing text on a message that had attachments **always poison-parks** the row (BRG-2, **[verified]**).
5. **Redundancy is now measurable**: 13 dead top-level shims (2 undocumented), ~30 zero-caller exports, 6 divergent `resolveOutbound` copies, 5 `escapeHtml` copies (two weaker than the others), ~10 more duplicate-helper clusters, and a half-wired invalidation/revocation subsystem (`invalidateUserGuild`, `invalidateSession`, `dashboardData.invalidate`, `voiceData.invalidate`, `markBridgeBroken`, `assertCommandContext` — all built, tested, zero production callers).

**Architecture verdict:** the 2026-10 structural prescriptions were adopted and are working; nothing needs ripping out. The new disease is **half-wired machinery** (guards/invalidation/contract-asserts built but never called) and **config surfaces that lie** (written never read, defaults bypass fail-fasts, settings that no longer match behavior). Cheapest systemic wins: a wiring-audit pass over every `export`ed guard/invalidator, and a CI check that every settings column has a reader.

### 1.4 Deterministic e2e failure — TEST bug, patch ready **[verified]**

`e2e-events-reminders-config.test.js` "one digest posted 0≠1" fails whenever the run crosses UTC midnight, because the test sets `hour_utc` from the **real clock** but forces a **+4h** tick; `digestDueBoundary` computes on the injected date → future boundary → digest never fires. Reproduced 2/2 locally; CI is green purely by time-of-day luck (fails for runs in the UTC 20:00–23:59 window). Product chain claim→gate→eligibility→send verified healthy. Test-only fix at `findings/E2-e2e-clockfix-suggested.patch` (matrix-verified 24/24 boundary hours). Until merged, **the 232-pass e2e claim carries a time-window asterisk**.
