# Deep Architecture Audit — 2026-10-04

Adversarial evaluation of the full codebase: 8 specialist audits over all 317 source files (~98K LOC), each instructed to distrust documentation and prior decisions. All Critical/High findings below were independently re-verified against primary source (marked **[verified]**). Baselines at audit time: unit 3,784 pass, integration 349 pass, coverage 88.95/76.41/87.80 (gate 77/67/77), `node --check` clean.

Status: **OPEN — remediation not started.** P0/P1/P2 lists at the end.

---

## 1. Executive Verdict

The codebase is **well-engineered at the layer boundaries** (repository discipline, web-console tenancy, scheduler, SQL injection-clean, no IDOR, excellent test isolation) and **systemically fragile at the integration seams** — specifically where a hand-written abstraction meets a real external contract (the Fluxer SDK, the gateway event shape, wall-clock time). The root architectural disease is precise and provable: **the 4,133-test suite verifies a model of the platforms, not the platforms themselves.** The four worst bugs below are all invisible to a fully-green suite by construction.

"Shipped" status semantics are the process-level twin of that disease: **Shipped = merged**, with live verification as a follow-up ceremony. Git history proves the consequence — Fluxer declared shipped v1.30.0 on Sep 30; within 3 days the first live pass found a crash on the most common interaction idiom across 9 files, a process-killing gateway crash, and a **pre-existing Discord-side user-facing break** (`!reactionrole` emoji flow throwing `community id required` — commit `85b71c3` records it as "a PRE-EXISTING main bug") that 3,784 green tests never caught.

## 3. Medium Findings (condensed)

- **Bridge:** connect-race leaks two orphan webhooks per failed activation (cleanup calls sit on return paths, not the throw path — `service.js:1044-1050`); multi-part messages poison-parked mid-list leave link-less copies that edit/delete relay can never find; spool dirs of disconnected bridges occupy the 2 GiB cap until restart; docs' "avatars are best-effort" is **false** — `httpsAvatarUrl` string-checks a method; no `MessageUpdate`/`MessageDelete` listeners on Fluxer at all, so moderation takedowns on Fluxer never propagate (docs promise bidirectional).
- **OAuth:** `/oauth/command-permissions/callback` skips the `purpose === "cmd_perms"` check its own module mandates (`httpCallback.js:93-104`) — cross-flow state substitution; concurrent token refresh deletes the guild's stored grant on the loser's `invalid_grant` (`oauthTokens.js:148-153`); state nonces in-memory only (restart replay window); `SESSION_SECRET`/`OAUTH_STATE_SECRET` both silently fall back to `CLIENT_SECRET` (key-domain coupling; rotating the Discord secret destroys stored session tokens).
- **Linking:** Fluxer `!link create` posts the code **in-channel** (Discord path is ephemeral) with default-on 100% XP/memory mirroring → passive link-squat: whoever redeems first owns a 100% mirror of the victim. The DM mechanism exists and bridge uses it; linking opts out. Link-conflict replies leak peer id/timestamp on non-ephemeral surfaces.
- **Tickets:** concurrent double-archive leaks an orphan transcript dir + duplicate DMs (check-then-act on in-memory flag; SQL guard is correct, the loser's directory is not swept); AI summary called with no timeout can stall archive indefinitely; `"unknown error"` replies at `lifecycle.js:169,356` violate the repo's own error rule 3; ticket-create rate-limit check-then-act race (rate-limit check and insert are separate statements).
- **XP/Leaderboard:** button customId page has no upper bound (`xp/index.js:201-202` **[verified]** — the slash arm clamps, the button arm doesn't): crafted `ui:lb:…:999999` = full-table materialization per click.
- **Tickers:** one bad guild aborts the whole voice tick (`voice/index.js:79-84`); decay aborts remaining users of a community on a single un-wrapped throw (`decay/index.js:269-349`) — the repo's own rule 5 (per-item accumulation) violated at loop level. Twitch: send-failure burns the go-live watermark permanently (`twitch.js:263-278`). Reaction roles: react/unreact interleave can strand a granted role with no reaction, unrecoverable (`reactionRoles/service.js:749-837`). `readPage` buffers the whole body before the 1 MB cap (chunked encoding bypasses the `Content-Length` check — `readPage.js:378`).
- **Migrations:** 003 rebuilds `youtube_channels` outside a transaction with a positional `SELECT *` (crash between DROP/RENAME = silent permanent data loss on next boot; every later migration adopted the transaction discipline — 003 is the pre-discipline outlier). Migration 016 exports no `id` → "Migration undefined failed" in logs. No version tracking at all (`PRAGMA user_version = 0` verified) — safety is 100% hand-written per-migration idempotency.
- **Config fail-opens:** `CLIENT_ID` documented-required, never validated (bot boots, registration/sync inert); `LAVALINK_PASSWORD` defaults to Lavalink's public default `"youshallnotpass"` (`lavalink.js:23`); `GORK_INTERACTION_LOG` on by default with 200K-char full transcripts, 30 days (privacy default to document).
- **Schema:** `db.allUsersInGuild` is `undefined` at runtime **[verified]** (facade maps a renamed export — `allUsersInCommunity`); `users.xp` has no CHECK constraint (better-sqlite3 stores `Infinity`; `clampXpTotal` converts non-finite to 9.007e15 — a poisoned cell poisons the leaderboard); FK coverage is 8 REFERENCES across 36 migrations and enforcement rides the driver default, not the code; `voice_sessions` is dead schema; `cleanupOldNotifications` is an armed, un-wired data-deleter that would delete 30-day-stale subscriptions if ever wired.
- **DB hot paths:** `getGuildSettings` is a write path (upsert on every read, on the message hot path); leaderboard sorts with a temp B-tree (`ORDER BY xp DESC` unindexed per community); `gork_usage` day-prune full-scans (no index on `day`); migration 005 full-scans `users` every boot.
- **Web:** transcript attachment `href` has no render-time scheme check (write side is `^https?`-filtered — defense-in-depth gap); `style-src 'unsafe-inline'` (documented concession); `/g/:id/system/sessions` is a deliberate cross-tenant read surface at admin tier; `music/resolve.js:65-66` passes arbitrary URLs to Lavalink (SSRF delegated to the node — document egress restriction).
- **Dead legacy shims** (`src/xp.js`, `decay.js`, `roles.js`, `reactionRoles.js`, `voiceTicker.js`, `renderLeaderboard.js`, `renderHoneypotWarning.js`, `auditLog.js`, `youtubeTicker.js`, `register-commands.js`, plus stubs in `commands/definitions.js`/`handlers.js`): zero importers; public API for external scripts per docs. `src/db.js` is the exception — 40+ consumers; keep it.

## 4. Root-Cause Patterns (the systemic critique)

1. **Fixture-shaped truth.** Every High-severity Fluxer bug (C1, C2, avatars, embeds) shares one cause: tests hand-build wire shapes; nothing asserts against real `@fluxerjs/core` models. `fluxer-sdk-import-guard.test.js` enforces the SDK is imported in exactly one src file — good for isolation, catastrophic for contract coverage. The mocks are the specification, and the specification is wrong.
2. **Duck-typed cross-platform contracts.** The pipeline spine keys shared features off `!message.guild` (`logs/auditLog.js:32`, `userActivity/service.js:163` **[verified]**), so Fluxer messages **silently** disable message audit and activity counters — zero logs, docs advertise them. The normalized contract has no required-field assertion; more of these will accrete. This is an architectural property of the seam, not a bug that can be closed once.
3. **Boolean flags standing in for state machines.** `archived=0` checked in-memory (double-archive), `sent_at IS NULL` conflating claim/deliverable/delivered (reminders), in-memory `usedNonces` (OAuth), `claimTwitchStream` read-then-write (safe only single-process). `bridges.js:701-721` (CAS outbox claim) is the correct pattern — it exists and isn't the norm.
4. **"Shipped = merged."** 16 of 19 shipped features cite PR numbers as evidence; only Fluxer/Bridge/web-admin have live-verification records — created *after* the label. fix:feat = 86:97, with fix clusters densely packed immediately after each "Shipped" label.
5. **Retention designed, never wired.** Indexes and comments promise pruning for three tables; no DELETE exists (verified). The enforcement mechanism ships three times for smaller tables.
6. **Docs drift is systematic, not incidental.** Verified-false claims include: registry "28 commands" (30); "23 features" (25); XP doc "270 XP/h" (arithmetic: 900); voice "one channel per minute" (all eligible channels are awarded); "XP can never reach zero via decay" (`floor(19×0.05)=0`); honeypot "staff are never banned" (two code paths); YouTube upload-role ping (suppressed); `docs/tickets.md` "not login-gated" (it is — stale in the safe direction); `docs/bridge.md` avatars/edits/deletes from Fluxer; `docs/decay.md` "configurable via cron" (`DECAY_CRON` is a hardcoded const); `docs/warnings.md` guild_id schema (stale vs 034); `docs/command-restrictions.md` "DMs bypass" (DMs run nothing; router early-returns on `!interaction.guild`); boot-sequence/feature-count sections of `docs/architecture.md`.

## 5. Architecture Verdict on the Big Decisions

| Decision | Verdict |
|---|---|
| **Modular monolith + feature registry + scheduler** | **Sound.** Scheduler is the strongest module (overlap-skip, error isolation, snapshots). 25 features over a clean registry. No change needed. |
| **Repository layer + dual facade** | **Sound.** 105 consumers on the stable path; zero SQL injection (every interpolation is code-owned). One dead binding (§3); 4 bridge functions bypass the repo boundary (safe today, splits the outbox state machine across two files). |
| **Web admin console** | **Sound and genuinely good.** Full route→authz audit found **no IDOR**: every data call keys off server-derived `req.guildAccess.communityId`; CSRF is structural (method-gate lockstep); CSP `script-src 'self'`; sessions rotate, hash, entropy-clean. The only High is C6 (token-at-rest asymmetry). |
| **Dual-platform (Fluxer) abstraction** | **Structurally sound, contractually broken.** The seam design is right (string-only ids, `deploymentKey` namespacing, dispatch-gating Discord-only handlers, `communities` table). What's missing is the **contract**: a runtime-asserted handle typedef (C1's root cause), SDK-shaped model tests (C2), and a normalized message shape with required fields (the duck-field deaths). Do not rip out the abstraction — finish it. |
| **Bridge design (webhooks + outbox)** | **Right architecture, incomplete state machine.** At-least-once with CAS claim + relay-nonce dedupe is correct; the gaps are per-part link commit, cleanup-on-throw, and the un-ingested Fluxer edit/delete event pair. The spec (KD "id-synchronous commit") was right; the implementation deferred it and the docs didn't record the deferral. |
| **Idempotent-replay migrations** (no version tracking) | **Workable for a single-process SQLite bot; one real debt:** 003 is the exact non-transactional data-move later hardened against in 034, and nothing records what has run. A `PRAGMA user_version` guard is ~10 lines. No down-migration story at all — acceptable for fix-forward SQLite with the documented backup discipline. |
| **Process: 6,760-line roadmaps, 43 releases in 9.5 weeks, for a self-described "single-server personal project"** | **The planning artifact outgrew its purpose.** The docs are a contract ledger written at agent-scale cost; the verification column is the one that stays blank. Cheapest corrective: one rule — *no feature is Shipped without a dated live-verification record* — which Fluxer/bridge already invented. |

What the audits **confirmed healthy** (for the record): fire-and-forget discipline (40/40 audited sites guarded), permissions model (no command is client-side-gated; every staff/admin command re-checks server-side), session entropy/rotation, CSRF structure, SSRF guards in gork `readPage`/`webSearch`/bridge media, OAuth state signing (signature + purpose binding + TTL + single-use nonce), XP caps at all input boundaries, migration idempotency with a full-re-run test, test isolation (temp DB per file, no shared state), no committed secrets, no committed build artifacts, clean TODO hygiene (5), high JSDoc coverage in core.

## 6. Prioritized Remediation

### P0 — ship this week (all small, all verified)

1. Expose `apiPublic` on the Fluxer handle; pass as `apiOrigin`; fail loudly on empty (C1).
2. `memberRoleIds: mapIdArray(member?.roleIds ?? member?.roles)` in Fluxer normalize + one test fed a real SDK `GuildMember` instance (C2).
3. Honeypot: ban only when the `oldMember` diff is known and the ban role is *newly* present; on member-fetch failure delete-and-log, **don't ban** (C3/C4).
4. Add `process.on("unhandledRejection")` logging net + `.catch()` at `boot.js:172` / `pipelines.js:453-471` + try/catch around the synchronous normalize (C8); SIGTERM/SIGINT drain using the existing `stop()` handles (C9).
5. YouTube ticker: `allowedMentions: { parse: ["roles"], roles: [uploadRoleId] }` (mirror `twitch/ticker.js:146-148`); add `"everyone"` to parse for live alerts if intended (H11).
6. Leaderboard button parser: apply the `LB_PAGE_MAX` upper bound at `xp/index.js:201` (one line).
7. Route ticket-asset downloads through the bridge's existing SSRF guard (C5).

### P1 — next cycle

- Encrypt `guild_command_permission_oauth` + `github_watches` tokens with the existing `tokenCrypto` envelope + one-time re-encrypt migration (C6).
- Boot gate: treat Discord login failure as terminal so features start on the surviving endpoint; add a watchdog log when features never start (C7).
- Decay: delta `UPDATE users SET xp = floor(xp*(1-pct))` inside a transaction — no snapshot arithmetic (H10); per-user try/catch.
- Add retention sweeps: `activity_log`, `admin_audit`, `user_channel_message_daily`, expired `fluxer_oauth_transactions` (the sweeper for link codes is the template).
- Add `purpose === "cmd_perms"` check in `httpCallback.js`; per-community single-flight on token refresh; never delete the grant on a refresh 400 that raced a winner.
- Fluxer `!link create` via the K2 DM path (bridge already uses it); drop peer detail from non-ephemeral conflict replies.
- Bridge: cleanup-on-throw in `activateBridge`; per-part link-row commit; TTL sweep on `echoMessageIds`/`destinationIds`; spool-dir delete on disconnect; wire `Events.MessageUpdate`/`MessageDelete` ingestion.
- Event reminders: real claim state (`sending`) + failure backoff + distinguish "channel gone" from "fetch failed" (H12).
- Tickets: CAS the archive flag before doing work; pass a timeout to `chatCompletion`.
- Voice/decay tickers: per-guild/per-user try/catch so one failure can't abort the tick.
- Docs at-risk surfaces: YouTube ping (add a ticker-level send-shape test — mock the transport, assert `allowedMentions`).

- **SDK-shaped contract tests**: import real `@fluxerjs/core` (dev-only), assert normalize/dispatch against actual model instances; add a pipeline test pushing one normalized Fluxer message through `onMessageCreate` and asserting every step's observable effect (cache row, activity row, XP row).
